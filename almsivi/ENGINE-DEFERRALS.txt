Manifest declaration syntax is PINNED SOURCE VERIFIED, not in-game proven. At OpenMW commit f4bec41444214a7903bebd178389ca22ca13f646, `files/data/builtin.omwscripts` contains GLOBAL, PLAYER, and CUSTOM declarations (CUSTOM at line 36), and `scripts/data/integration_tests/test_lua_api/test_lua_api.omwscripts` contains GLOBAL and PLAYER declarations. `ALMSIVI.omwscripts` uses only those verified declaration forms.

These seams still require the pinned OpenMW 0.51.0/API-129 integration and in-game proof; pure Lua fakes do not prove them:

- GLOBAL active-object identity extraction, onPlayerAdded/onActorActive coverage, and RefNum/content/cell reads.
- PLAYER semantic action registration/default bindings, camera ray, nearby-object query, and actual widget/text-edit construction.
- Dynamic CUSTOM script attach/remove calls and actor-local event routing.
- ai.follow package invocation/restoration and engine expiry-clock conversion.
- Opaque actor-positioned speech and stop calls; no path-based substitute is implemented.
- Native openmw.almsivi queue/backpressure, transport, cancellation, halt, status, capability, and token guarantees.
- Actual save callbacks, menu/disconnect/profile lifecycle signals, and vanilla dialogue-response event shape.
- In-game permission/context tests, UI appearance, activation non-regression, actor detach, and dialogue delivery.

The modules keep these calls behind adapters/capabilities. Target distance and text-size policy are required but have no numeric value in the plans, so they must be supplied by verified/configured adapters and negotiated caps rather than claimed as protocol constants. Transcript retention and picker row limits are optional UI-local policy inputs and have no compatibility meaning. The Python fallback is structural only because no Lua interpreter was available during this change.
