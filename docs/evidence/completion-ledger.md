# Completion and proof ledger

The authoritative current-checkpoint rows are in `proof-ledger.json` and use the states defined by `docs/PROGRAM-PLAN.md`. `AUTOMATED` means a repeatable no-game check actually passed; it never means a platform build, integrated engine, Lua runtime, mod-loader, compatibility, or game behavior passed. `PLANNED` identifies checked-in automation or a future platform lane that has not supplied qualifying execution evidence. `WINDOWS BUILD PROVEN`, `IN-GAME PROVEN`, and `COMPATIBILITY PROVEN` require evidence from those exact environments. `DEFERRED` rows state their resume condition. Run manifests attest only to the command, inputs, outputs, tools, and result they contain.

The repository contains repeatable patch, protocol/fake-server, pure-native, Lua structural, packaging, and audit commands. Execution outcomes become `AUTOMATED` only when a committed run manifest produced against a clean commit records success. Engine integration, Lua runtime, sanitizer runtime, and platform results remain unproven.

CI platform rows are `PLANNED`, not `AUTOMATED`: definitions are automation, not evidence they executed. Lua runtime, exact-pin OpenMW integration/control builds, Beast live transport, final `SYNTH`/`Synthserver` import/migration/cross-repository parity, Windows build/game/mod evidence, and release/signing/publication remain deferred. No deferred source was read or imported, and workflows or mocks are not promoted to game or platform proof.
